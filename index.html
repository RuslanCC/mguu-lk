01

Что будет в кабинете

Один кабинет для студента и рабочее место для сотрудников. Работает в браузере и устанавливается на телефон как приложение.

Доступ

Вход и регистрация

Студент регистрируется сам: кабинет сверяет его данные через API университета, студент задаёт пароль.

Кабинет

Профиль, расписание и зачётка

ФИО, группа, направление, курс и статус — из API университета. Расписание и оценки — если API их отдаёт.

Связь

Сообщения

Личные сообщения и чаты групп и курсов, вложения, доставка в реальном времени. Сотрудники модерируют общие чаты.

Анонимные и именные опросы для групп, курсов и направлений; результаты в кабинете и выгрузка в Excel.

Новости

Уведомления и объявления

Объявления деканатов и кафедр, push-уведомления на телефон и в браузере.

02

Как кабинет получает данные

API университета отдаёт сведения по одному студенту за запрос. Массовой выгрузки не нужно: кабинет запрашивает данные тогда, когда студент входит.

  1. Студент
  2. Кабинет на ВМ университета
  3. API университета
  4. Кэш профиля

Регистрация

Студент вводит ФИО, дату рождения и номер мобильного телефона. Кабинет сверяет их через API, студент задаёт пароль. Дату рождения и телефон кабинет не хранит. Забытый пароль сбрасывает сотрудник деканата.

Вход

При каждом входе профиль обновляется из API. Если API недоступен, студент видит последние сохранённые данные.

Отчисление и выпуск

Если API сообщает, что студент больше не учится, доступ закрывается при следующем входе или ночной проверке.

Группы для опросов

Группы и курсы складываются из профилей вошедших студентов. Деканат может загрузить список группы заранее.

Сотрудники

API отдаёт только студентов, поэтому сотрудников заводят в админке — вручную или списком.

Бережная нагрузка

Запросы к API ограничены по частоте и записываются в журнал: кто, когда и какие данные запросил.

    05

    Что нужно от университета

    План короткий, поэтому сроки ответа важны: доступы — в первую неделю, ответы на запросы — до 3 рабочих дней.

    ИТ-служба

    Три виртуальные машины с бэкапом на гипервизоре и VPN к 13 ноября. Рабочий адрес и сертификат к 23 декабря. С пилота — первая линия поддержки.

    Подразделение, которое ведёт 1С

    Какие методы 1С уже есть — к 11 ноября. Тестовый доступ с описанием методов — к 13 ноября, новый метод сверки, если нужен, — к 23 ноября. Рабочий доступ — к 23 декабря.

    Учебный отдел и деканаты

    Состав опросов и рассылок, пилотные группы, сотрудники для админки, верные номера телефонов в 1С, приёмка на стенде.

    ИБ и юрист

    Решения по ОС и доступу разработчиков — к 13 ноября, модель угроз — к 30 ноября, согласие и положение о кабинете — к 18 декабря, проверка мер защиты — к 30 декабря.

    Студенческий совет

    Обсуждение прототипов в ноябре, участие в пилоте в январе.

    Кабинет и все данные — на ВМ университета. Бэкап — ежедневные снимки ВМ на гипервизоре университета, проверка восстановления — до пилота.

    БэкапЕжедневные снимки всех трёх ВМ на гипервизоре, хранение не менее 7 дней—

    Ограничение. Три машины не дают дублирования: при сбое ВМ кабинет восстанавливается из копий за несколько часов, данные за последние сутки могут быть потеряны. Для учебного кабинета этого достаточно; резервная площадка — в следующей очереди.

    Информационная безопасность и персональные данные

    Требования

    • ФЗ-273, ст. 16 — электронная информационно-образовательная среда.
    • 152-ФЗ — хранение в РФ, отдельное согласие на обработку; ПП № 1119.
    • Приказ ФСТЭК № 21 — меры защиты персональных данных.
    • Приказ ФСТЭК № 117 — защита ИС государственных учреждений. Кабинет — не ГИС.

    Меры

    • Данные только на ВМ университета, персональные данные во внешние сервисы не передаются. Push идёт через серверы Google, Apple, Mozilla и Microsoft и содержит только сигнал, без имён и текста.
    • Согласие на обработку данных — при регистрации.
    • Шифрование трафика.
    • Журнал запросов к API и действий в админке.
    • Рабочий контур — к 28 декабря 2026, проверка мер защиты — к 30 декабря, до пилота.
